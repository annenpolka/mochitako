# 人の好みを起点に辞書を育てる

2026-09-11、ユーザーが提示した「人間評価 → LLM評価器 → 辞書拡張」の方向を採用。
辞書が主成果物、生成器は利用例という既存方針を維持する。
この文書は今後の方向と検証条件。記載したLLM機能は未実装・未実行。

## 目的

語数だけでなく、使いたくなる名前と、既存語とは違う表現の広がりを増やす。
人は10問の2択で好みを伝え、LLMは比較の予測・レビュー対象の選別・候補語生成を担う。
採用判断の根拠となる人間回答を保持し、モデルの予測で置き換えない。

## 1. 人間回答を蓄積する

現在の `pnpm eval:serve` と `evaluation/results/` の保存を利用する。
原則は片側を固定した2択。少数の名前全体の比較も混ぜる。
モデル評価に進むために、5軸採点や理由記入を必須にしない。

- 訂正は同じ比較の最新回答を有効とし、保存履歴を別の独立回答として数えない。
- スキップは敗北・同点・badに変換しない。
- AがBに勝っても、Aをgolden、Bをbadとは断定しない。
- 「使いたい割合」や絶対品質が必要になった段階で、少量の別質問を足す。
- 30〜50件は最初の試行時期の案。100件・300件などの件数で品質を保証しない。

## 2. LLM評価器を小さく検証する

最初の実装対象は、保存済み回答から再現可能な実験データを作り、
例なしの評価と人間の選好例を与えた評価を同一条件で比較すること。
モデルと実行手段は実行時に明示し、使用量・費用が不明なら不明のまま記録する。
全件評価に進む前に小規模実行の結果と費用を確認する。

例示用と検証用は、プロンプト作成前に固定して分離する。
A/Bを反転した同じ比較や、同じ比較の訂正版を別の分割へ漏らさない。
検証回答はプロンプト例・rubric調整に利用しない。調整に使った検証セットは開発用に格下げし、
新しい検証セットを用意する。必要なら語を共有しない検証も設け、新語への一般化を別に測る。

比較するもの：

- 同じモデルの例なし評価と、少数の人間選好例を与えた評価。
- 未提示の人間選択との一致数／検証数。少数件では割合だけを強調しない。
- A/Bを交換したときの整合性と、同じ比較の反復での揺れ。
- 回答不能・形式エラー・未実行件数。都合よく分母から消さない。
- 役割・語群ごとの差、検証データの偏り、実行使用量。

評価器を使う条件は検証前に定める。初回の少数データで全辞書への精度を断定しない。
LLMが出す自信の数値だけで「確実」と扱わず、反復不一致や順序依存も確認する。

## 3. 人が見る比較を絞る

まず限定した未評価ペアで試し、検証できた範囲から広げる。
人へ戻すのは、予測が割れる比較、未登場の語、少ない意味領域の候補。
加えて均等ランダムな比較を残し、モデルが得意な領域だけに閉じないようにする。

全23,100ペアの列挙と、全比較の評価は異なる。
23,100個を互いに比較すれば約2.67億比較になるため、総当たり対戦はしない。
必要に応じて共通の基準例との比較や、接続された比較設計を用いる。
分類する場合は人が確認したカテゴリ基準を別途用意する。
相対選好だけからlegendary率やacceptable数を作らない。

モデル予測は人間回答と別保存し、モデル・プロンプト版・辞書ハッシュ・
例示データID・生出力・失敗・使用量を追跡できるようにする。
予測を人間ラベルに混ぜたり、予測だけで評価器自身の正しさを測ったりしない。

## 4. 候補語で辞書を拡張する

現在のタグ分布と人の回答から、探索する意味領域を提案する。
タグの少なさは探索の入口であり、埋めるべき欠点と決めつけない。
新領域の提案は既存kind/vibesスキーマへの自動追加とは分ける。

1. LLMが候補語と読み・想定役割・狙う表現領域を提案する。
2. 実在・表記・ローマ字化・既存value/readingとの重複を確認する。
3. 意味が近い語は削除確定せず、冗長性の確認対象にする。
4. prefix候補なら全既存suffix、suffix候補なら全既存prefixと組み合わせる。
5. 校正した評価器で予測し、高評価・低評価・意外な組み合わせを人へ示す。
6. 少数の候補について、人が既存語との差と名前の良さを確認する。
7. 採用・保留・却下の理由を残し、採用語は辞書の通常検査を通す。
8. 人が実際に判定した回答だけを次の評価例へ追加する。

両役割を持つ語は追加ペアの重複を除いて数える。候補をまとめて追加する際は、
候補同士のペアと候補間の冗長性も調べる。単語ごとの予測gainを単純合算しない。

候補の比較では、予測される良いペア数、好ましくないペア数、既存語との違い、
人の確認件数を分けて表示する。根拠のないnoveltyの小数や加重総合点を作らない。
語の採用は人のレビューを経て進める。予測が低い候補でも新しい表現を持つなら保留できる。

## 次に行うこと

1. 既存10問を取り込み、実回答の保存内容を確認する。
2. 10問単位で無理なく回答を増やす。
3. 例示／検証の分割と、LLMへ渡すpairwiseプロンプト・rubricを実装する。
4. 小規模な実モデル評価で、例示の効果・失敗・費用を報告する。
5. その結果を見て評価範囲と候補語生成へ進むかを決める。
